HoL Build 1 — Foundation

Instruksi lengkap dan final untuk membangun fondasi HoL: shell aplikasi, input manual, Today & Overdue, riwayat, dan lapisan data yang bisa ditukar ke Supabase tanpa menyentuh satu baris kode antarmuka. Tanpa AI. Tanpa database. Tanpa notifikasi.

Cara memakai dokumen ini. Buka percakapan baru dengan Sonnet 5, tekan Salin untuk Sonnet di kanan atas, tempel isinya, lalu lampirkan Standar_Coding_Anabhi_Dev.md dan logo HoL. Jangan lampirkan PRD lengkap, Notification Addendum, atau SOP Checklist di Build 1 — konteks yang tidak relevan menurunkan kualitas hasil, bukan menaikkannya.
01

Ringkasan Build 1

Build 1 punya satu tujuan tunggal: HoL bisa dipakai mencatat hidup pada hari yang sama saat ia selesai dibangun. Bukan demo, bukan mockup — aplikasi sungguhan yang datanya bertahan setelah browser ditutup.

Kenapa tanpa AI dulu

Parsing Gemini adalah fitur unggulan, tapi bukan fondasi. Kalau schema dan alur simpan belum matang, hasil parsing tidak punya tempat yang benar untuk mendarat. AI dibangun di Build 4, di atas struktur yang sudah terbukti.

Kenapa tanpa Supabase dulu

Menyiapkan Auth, RLS, dan migrasi di hari pertama berarti berjam-jam sebelum layar pertama muncul. Dengan Data Adapter, pindah ke Supabase di Build 3 hanya mengganti satu implementasi — bukan menulis ulang.

Kenapa report ditunda

Report butuh data nyata. Grafik dari data kosong tidak mengajari apa pun. Yang penting sekarang adalah merekam field yang benar supaya Build 2 punya bahan. Itu urusan schema, bukan urusan chart.

Ukuran keberhasilan

Bukan jumlah fitur. Build 1 berhasil kalau setelah lima hari pemakaian nyata, mencatat aktivitas terasa lebih cepat daripada menulisnya di Notes.

Target hosting: anabhidev.com/HoL/index.html — sebuah subpath, bukan root domain. Ini punya konsekuensi teknis nyata yang dibahas di bagian 12 dan 13. Semua path aset wajib relatif.

03

Aturan Tidak Bisa Ditawar

Tujuh aturan berikut menentukan apakah Build 3 dan Build 4 nanti berjalan mulus atau berubah jadi penulisan ulang.

  1. Semua akses data lewat Data Adapter. Tidak boleh ada satu pun localStorage.getItem atau localStorage.setItem di luar berkas js/store/local.js. Ini aturan yang paling sering dilanggar tanpa sadar, dan pelanggarannya baru terasa saat Build 3 — ketika sudah terlambat.
  2. Filter, urutan, dan pencarian dijalankan di dalam adapter. Antarmuka mengirim objek filter, adapter mengembalikan hasil yang sudah jadi. Kalau antarmuka menerima seluruh data lalu memfilter sendiri, migrasi ke Supabase berarti menulis ulang setiap tampilan.
  3. Waktu disimpan sebagai ISO 8601 UTC, dihitung dan ditampilkan di Asia/Makassar. Seluruh urusan waktu melalui satu modul. Tidak ada new Date() liar yang tersebar di berkas tampilan.
  4. Overdue tidak pernah disimpan. Ia selalu diturunkan saat render dari planned_at, is_all_day, dan status. Status yang tersimpan hanya lima: planned, in_progress, done, skipped, cancelled.
  5. Nama field memakai snake_case, identik dengan nama kolom Postgres nanti. Nol lapisan pemetaan di Build 3. Ini keputusan lima detik yang menghemat berjam-jam.
  6. Tidak ada angka statistik yang ditulis langsung di markup. Setiap angka dihitung dari data tersimpan, atau tidak ditampilkan sama sekali.
  7. Tanpa framework dan tanpa langkah build. Vanilla JS dengan ES Modules, dimuat lewat <script type="module">. Tidak ada React, tidak ada bundler, tidak ada pustaka chart di Build 1.
Untuk Sonnet: kalau salah satu aturan di atas terasa menghambat saat mengerjakan, jangan diam-diam melanggarnya. Hentikan pekerjaan, jelaskan hambatannya, dan tunggu keputusan. Melanggar aturan arsitektur secara senyap adalah kegagalan yang paling mahal, karena baru ketahuan berminggu-minggu kemudian.

Kontrak Data Adapter

Ini bagian terpenting di seluruh Build 1. Kontrak ini adalah satu-satunya alasan Build 3 nanti bisa selesai dalam satu akhir pekan alih-alih tiga. 

// js/store/adapter.js — kontrak, bukan implementasi

export class AdapterError extends Error {
  // code: 'NOT_FOUND' | 'VALIDATION' | 'STORAGE_FULL' | 'UNAVAILABLE'
  constructor(code, message, details) { ... }
}

/**
 * Setiap implementasi WAJIB menyediakan seluruh method di bawah.
 * Semua method async. Semua mengembalikan objek biasa, bukan instance class.
 * Adapter tidak boleh menyentuh DOM sama sekali.
 */

ready()                      // Promise<void> — siapkan storage, migrasi schema

list(filter)                 // Promise<Activity[]>
  // filter = {
  //   from, to,            ISO string, rentang planned_at (inklusif)
  //   status,              array status, kosong = semua
  //   category,            array kategori
  //   tags,                array tag, logika AND
  //   q,                   pencarian teks pada title + notes
  //   include_deleted,     default false
  //   sort,                'planned_at' | 'created_at' | 'updated_at'
  //   order,               'asc' | 'desc'
  //   limit, offset
  // }

count(filter)                // Promise<number> — filter sama persis dengan list()
get(id)                      // Promise<Activity | null>
create(draft)                // Promise<Activity> — adapter yang membuat id & timestamp
update(id, patch)            // Promise<Activity> — patch parsial, bukan replace
remove(id)                   // Promise<void> — soft delete, isi deleted_at
restore(id)                  // Promise<Activity>
purgeDeleted(beforeIso)      // Promise<number> — hapus permanen

exportAll()                  // Promise<{ schema_version, exported_at, activities }>
importAll(payload, mode)     // mode: 'replace' | 'merge'
                             // Promise<{ inserted, updated, skipped, errors }>

stats()                      // Promise<{ total, by_status, oldest, newest }>
                             // dipakai Settings; Build 2 memperluasnya

Aturan implementasi

  • id dibuat adapter memakai crypto.randomUUID() — jangan pakai timestamp atau penghitung, karena akan bentrok saat merge import.
  • created_at dan updated_at diisi adapter, bukan oleh pemanggil. Pemanggil tidak boleh bisa memalsukannya.
  • Validasi terjadi di domain/activity.js dan dipanggil adapter sebelum menulis. Gagal validasi melempar AdapterError('VALIDATION', ...) dengan details berisi field mana yang bermasalah.
  • Implementasi localStorage menyimpan seluruh koleksi dalam satu key, memuatnya sekali ke memori saat ready(), dan menulis kembali dengan debounce 300 ms. Membaca dan mem-parse seluruh basis data pada setiap ketikan pencarian akan membuat aplikasi terasa berat.
  • Tangani QuotaExceededError secara eksplisit menjadi AdapterError('STORAGE_FULL', ...), dengan pesan yang menyarankan export lalu hapus data lama.
Uji kontraknya, bukan implementasinya. Tulis satu berkas kecil js/store/contract.test.js berisi urutan langkah: create → get → list berfilter → update → remove → list (harus hilang) → restore → export → import ke penyimpanan kosong → bandingkan. Jalankan manual dari konsol lewat sebuah tombol tersembunyi di Settings. Di Build 3, berkas yang sama dijalankan terhadap adapter Supabase. Kalau lulus, migrasi selesai. Ini investasi tiga puluh menit yang menghemat satu akhir pekan penuh.

Aturan turunan status

  • Terlambat (all-day): planned_at jatuh sebelum hari ini di WITA, dan status masih planned atau in_progress.
  • Terlambat (berjam): waktu planned_at sudah lewat dari sekarang, dan status masih planned atau in_progress.
  • skipped dan cancelled tidak pernah terlambat. Keduanya sudah merupakan keputusan sadar.
  • Saat status jadi done, isi completed_at. Saat dibatalkan dari done, kosongkan kembali.
  • Saat pengguna menunda: kalau original_planned_at masih kosong, salin nilai planned_at lama ke sana lebih dulu. Baru kemudian ubah planned_at dan naikkan postpone_count. Urutan ini penting.
07

State & Rendering

Tanpa framework, disiplin harus datang dari aturan yang eksplisit.

Satu sumber kebenaran

const state = {
  route     : 'today',     // today | log | activity | settings
  filters   : { ... },     // dikirim apa adanya ke adapter.list()
  items     : [],          // hasil terakhir dari adapter
  editing   : null,        // id yang sedang diedit
  loading   : false,
  error     : null,
  toast     : null,
};

Aturan render

  • Event delegation, bukan listener per kartu. Satu pendengar di kontainer daftar, membaca data-action dan data-id dari elemen terdekat. Dengan ratusan kartu, listener per kartu merusak INP dan membocorkan memori.
  • Jangan render ulang seluruh daftar untuk satu perubahan status. Perbarui simpul kartu yang bersangkutan saja. Selain soal kecepatan, render ulang penuh membuat posisi gulir melompat — dan itu terasa murah saat dipakai.
  • Setiap teks dari pengguna wajib melewati escapeHtml(). Judul aktivitas, catatan, lokasi, tag. Walaupun ini aplikasi satu pengguna, celah XSS adalah hal pertama yang dilihat klien teknis saat menilai portofolio.
  • Tiga keadaan wajib untuk setiap tampilan: sedang memuat, kosong, dan gagal. Keadaan gagal harus menyebutkan apa yang terjadi dan apa yang bisa dilakukan — bukan sekadar “Terjadi kesalahan”.
  • Router berbasis hash (#/today, #/log, #/a/<id>). History API tidak dipakai karena akan bermasalah pada hosting statis di subpath tanpa aturan rewrite.
Bahasa antarmuka. Gunakan Bahasa Indonesia untuk seluruh label yang dilihat pengguna, dan bahasa Inggris untuk nama kode, field, serta komentar. Tombol diberi nama sesuai apa yang terjadi: Simpan, Tandai selesai, Tunda, Hapus. Nama aksi tidak berubah di sepanjang alur — tombol Simpan menghasilkan notifikasi Tersimpan, bukan Berhasil.

Tipografi

Ini pembeda terbesar antara HoL dan aplikasi tugas korporat mana pun. Dua jenis huruf, dengan pembagian tugas yang tegas.

Georgia — editorial

Judul halaman, judul report, dan angka besar. Serif memberi rasa jurnal pribadi, bukan papan tugas. Inilah nada emosional yang diminta PRD: “ternyata bulan lalu saya ngapain aja ya?”

System UI stack — antarmuka

Label, tombol, isi kartu, form. Nol permintaan jaringan, render instan, dan terasa asli di setiap perangkat.

Keputusan: tanpa web font di Build 1. Georgia tersedia di hampir semua perangkat dan berbiaya nol byte. Kalau nanti terbukti Georgia kurang khas, penggantinya cukup satu baris di tokens.css.

Layout & Navigasi

Desktop — 1024 px ke atas

  • Sidebar tetap di kiri, lebar 264 px, latar navy-900.
  • Header lengket di atas, tinggi 64 px, menempati sisa lebar di kanan sidebar.
  • Judul di header: History of Life — bukan hanya “HoL”.
  • Konten utama memakai calc(100% - 264px) dengan pembatas isi maksimum 1120 px agar baris teks tidak terlalu panjang, tetapi kartu dan daftar tetap boleh melebar penuh.

Mobile — di bawah 1024 px

  • Sidebar berubah jadi laci yang meluncur dari kanan, lebar min(300px, 86vw).
  • Tombol hamburger berada di sisi kanan navbar, sejajar ibu jari. Judul History of Life di kiri.
  • Lapisan gelap di belakang laci; menyentuhnya menutup laci. Tombol Esc juga menutup.
  • Saat laci terbuka: kunci gulir badan halaman, pasang perangkap fokus di dalam laci, dan kembalikan fokus ke tombol hamburger saat ditutup.
  • aria-expanded pada tombol wajib diperbarui setiap kali status berubah.
Catatan untuk aplikasi HoL (bukan dokumen ini). Untuk sebuah aplikasi yang dipakai berkali-kali setiap hari, laci saja biasanya kurang. Navigasi bawah dengan empat tab dan satu tombol tambah yang menonjol biasanya lebih baik. Ini termasuk keputusan terbuka di bagian 18 — jangan diputuskan sepihak oleh Sonnet.

Titik uji lebar layar

Uji pada 320, 360, 390, 768, 1024, 1280, dan 1920 px. Angka 320 px bukan formalitas: di lebar itulah kartu dengan beberapa pil metadata biasanya mulai memaksa halaman menggulir menyamping.

12

Bagian Tersulit

Delapan hal berikut adalah tempat pekerjaan ini paling mungkin gagal secara halus — terlihat jalan, padahal salah. Kerjakan dengan perhatian lebih, dan uji secara khusus.

  1. Logika zona waktu Tersulit Date di JavaScript bekerja dalam zona waktu perangkat. Kalau perangkat diatur ke UTC — atau kakak sedang bepergian — batas “hari ini” bergeser, dan aktivitas bisa tiba-tiba dianggap terlambat padahal belum. Solusinya: seluruh perhitungan tanggal melewati domain/time.js, dan komponen tanggal diambil lewat Intl.DateTimeFormat dengan timeZone: 'Asia/Makassar', bukan lewat getDate() mentah. Fungsi wajib: nowWita(), dayKey(date), startOfDayWita(date), isOverdue(activity, now), formatRelative(date).
    Uji: ubah zona waktu sistem ke UTC lalu ke Asia/Jayapura. Daftar “Hari ini” harus berisi aktivitas yang persis sama.
  2. Dua aturan terlambat yang berbeda Halus Aktivitas sehari-penuh baru terlambat setelah hari itu berakhir di WITA. Aktivitas berjam terlambat begitu jamnya lewat. Menyamakan keduanya menghasilkan pemberitahuan palsu sepanjang hari, dan itu persis yang membuat orang berhenti memakai aplikasi semacam ini.
  3. Progressive disclosure tanpa kehilangan isian Saat pengguna membuka lalu menutup bagian “Detail lainnya”, nilai yang sudah diketik tidak boleh hilang. Artinya bagian itu disembunyikan lewat CSS, bukan dilepas dari DOM — dan validasi hanya berlaku untuk field wajib, tidak untuk field opsional yang kebetulan sedang tersembunyi.
  4. Filter tetap berada di dalam adapter Godaan besar Menyaring array di tampilan terasa jauh lebih mudah dan akan sangat menggoda. Kalau itu terjadi, Build 3 berubah dari “ganti satu berkas” menjadi “tulis ulang semua tampilan”.
  5. Laci navigasi yang benar-benar aksesibel Perangkap fokus, aria-expanded, menyembunyikan konten belakang dari pembaca layar, mengunci gulir badan tanpa membuat halaman melompat, dan mengembalikan fokus saat ditutup. Hampir semua implementasi berhenti di setengah jalan, dan sisanya baru terasa saat dipakai dengan keyboard.
  6. Batas dan sifat sinkron localStorage Kapasitasnya sekitar 5 MB dan setiap operasinya memblokir. Muat sekali ke memori saat ready(), tulis kembali dengan debounce, dan tangani QuotaExceededError dengan pesan yang menyarankan export lalu bersihkan data lama.
  7. Deploy di subpath /HoL/ Semua path relatif. Sebelum deploy, cari seluruh berkas untuk pola src="/ dan href="/ — hasilnya harus nol.
  8. Import JSON yang tahan versi Berkas export wajib memuat schema_version. Saat import, periksa versinya; kalau lebih tinggi dari yang dikenali aplikasi, tolak dengan pesan jelas alih-alih memaksa membaca. Aturan ini hanya berbiaya sepuluh menit sekarang, dan menyelamatkan data kakak nanti.

Acceptance Criteria

Khusus Build 1. Verifikasi satu per satu dengan benar-benar mencobanya, bukan dengan membaca kode.

0 dari 20 terverifikasi
  • Aktivitas baru bisa dibuat hanya dengan mengisi judul, tanggal, dan kategori.
  • Seluruh field opsional bisa dibiarkan kosong tanpa memicu peringatan.
  • Aktivitas tanpa jam dan aktivitas berjam ditampilkan berbeda.
  • Aktivitas yang lewat tanggal dan belum selesai muncul di bagian Terlambat.
  • Aktivitas berstatus skipped atau cancelled tidak pernah muncul sebagai terlambat.
  • Menandai selesai mengisi completed_at; membatalkannya mengosongkannya kembali.
  • Menunda menaikkan postpone_count dan mengisi original_planned_at hanya pada penundaan pertama.
  • Menghapus bersifat soft delete dan bisa diurungkan lewat toast dalam 6 detik.
  • Pencarian teks menemukan kata di judul maupun catatan.
  • Filter kategori, status, dan rentang tanggal bisa digabungkan.
  • Tidak ada kode localStorage di luar js/store/local.js.
  • Uji kontrak adapter berjalan lolos dari Settings.
  • Export JSON menghasilkan berkas ber-schema_version, dan bisa di-import kembali dengan hasil identik.
  • Demo data bisa ditambahkan dan dihapus, dan tidak pernah tercampur diam-diam dengan data nyata.
  • Tiga empty state berbeda muncul di situasi yang tepat.
  • Data bertahan setelah browser ditutup dan dibuka kembali.
  • Pada lebar 320 px tidak ada gulir menyamping sama sekali.
  • Laci mobile terbuka dari kanan, tertutup oleh Esc dan sentuhan lapisan gelap, serta mengembalikan fokus.
  • Aktivitas dibuat pukul 23.30 WITA tetap terhitung sebagai hari yang sama.
  • Konsol bersih: tidak ada error dan tidak ada sisa log.

Definition of Done

Dipakai sungguhan

Minimal lima hari pemakaian nyata oleh kakak sendiri, bukan hanya diuji sekali jalan.

Lighthouse mobile

Performance dan Accessibility masing-masing minimal 90, diukur pada halaman yang sudah di-deploy.

Perjalanan data utuh

Export lalu import ke penyimpanan kosong menghasilkan isi yang identik, tanpa kehilangan satu field pun.

Tidak ada tombol mati

Setiap kontrol yang terlihat bisa ditekan memang melakukan sesuatu. Yang belum siap ditandai jelas sebagai belum tersedia.

Sudah tayang

Sudah berjalan di anabhidev.com/HoL/index.html, bukan hanya di komputer lokal.

Bahan portofolio siap

Tiga tangkapan layar bersih: Today di desktop, Today di mobile, dan riwayat dengan filter aktif.
