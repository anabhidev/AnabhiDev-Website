HoL — History of Life

Aplikasi personal life & activity system untuk mencatat apa yang ingin dilakukan, apa yang sedang dikerjakan, dan apa yang sudah dilakukan — kemudian mengubah seluruh aktivitas tersebut menjadi sejarah kehidupan yang dapat dicari, dipahami, dan dianalisis.

Core idea: Plan your life. Remember what you did. Understand your life.
02

Product Vision

🧠

External Memory

HoL membantu user mengingat apa yang ingin dilakukan dan apa yang sebelumnya belum selesai.

🤖

Natural AI Capture

User cukup menulis atau menceritakan aktivitas secara natural. Gemini membantu merapikan informasi.

📊

Life Analytics

Aktivitas sehari-hari tidak hilang setelah selesai. Semuanya menjadi data yang dapat divisualisasikan dalam report.

03

Problem & Opportunity

Masalah utama

User sering memiliki banyak hal yang ingin dilakukan tetapi lupa, tertunda, atau tidak pernah dicatat. Setelah aktivitas dilakukan, sebagian besar aktivitas tersebut juga hilang tanpa jejak yang mudah dicari kembali.

Opportunity

Menggabungkan task planning, activity logging, personal history, AI parsing, dan visual analytics dalam satu sistem yang tetap sangat sederhana pada saat input.

HoL bukan sekadar to-do list. To-do yang selesai menjadi history. History yang terkumpul menjadi report. Report membantu user memahami pola kehidupannya.

05

Activity Lifecycle

01 · Input User menulis natural language.
02 · Parse Gemini mengurai informasi.
03 · Review User memeriksa dan mengedit.
04 · Save User sendiri yang mengonfirmasi.
05 · Track Planned → In Progress → Done.
06 · History Activity menjadi bagian dari life history.
AI tidak boleh auto-save. Semua hasil parsing harus dapat diperiksa dan dikoreksi user sebelum data masuk ke sistem.

Planned

Aktivitas direncanakan untuk waktu tertentu.

In Progress

Aktivitas sedang dikerjakan.

Done

Aktivitas selesai dan menjadi bagian dari history.

Skipped

Aktivitas dilewati tanpa dianggap selesai.

Cancelled

Aktivitas dibatalkan secara eksplisit.

06

Home Experience

Quick AI Input

Area paling cepat untuk menulis aktivitas secara natural. Contoh: "Besok jam 9 service motor di Tabanan."

Today

Aktivitas hari ini dengan status Planned, In Progress, dan Done.

Overdue

Aktivitas sebelumnya yang belum selesai sehingga user tidak lupa.

Upcoming

Aktivitas yang akan datang sehingga user dapat melihat agenda tanpa membuka kalender eksternal.

Home = Memory + Action. User membuka HoL terutama untuk mengetahui apa yang perlu dilakukan, apa yang tertunda, dan apa yang baru selesai.
07

AI Parsing & Review

Example input

"Besok jam 9 service motor di Tabanan, sekalian ganti oli. Siang lanjut bikin report HoL."

Expected parsing

Activity Category Date/Time Context
Service motor Personal / Vehicle Besok 09:00 Tabanan
Ganti oli Personal / Vehicle Besok 09:00 Tabanan
Lanjut membuat report HoL Vibe Coding / Project Besok siang HoL

AI responsibilities

Mengidentifikasi activity, category, subcategory, date, time, location, cost, duration, hashtag, dan informasi lain yang memang tersedia dalam kalimat.

User responsibilities

Memeriksa hasil parsing, melakukan koreksi atau penambahan, kemudian secara eksplisit menekan tombol Save.

08

History

Planned Date

Tanggal/waktu ketika aktivitas direncanakan untuk dilakukan.

Completed Date

Tanggal/waktu aktual ketika aktivitas ditandai selesai.

Pemisahan Planned Date dan Completed Date memungkinkan HoL menghitung aktivitas tepat waktu, terlambat, masih pending, atau tidak dikerjakan.

Activity Data Model

Field Required Description
Activity YES Deskripsi utama aktivitas.
Category YES Kategori utama hasil AI/user correction.
Date YES Tanggal aktivitas.
Status YES Planned, In Progress, Done, Skipped, Cancelled.
Planned Date YES Tanggal/waktu yang direncanakan.
Completed Date Conditional Diisi ketika aktivitas selesai.
Subcategory Optional Detail kategori.
Hashtags Optional AI-generated dan dapat diedit user.
Location Optional Lokasi aktivitas jika tersedia.
Cost Optional Biaya aktivitas jika ada.
Duration Optional Durasi aktivitas jika relevan.
Photo Optional Dokumentasi visual.
Notes Optional Catatan tambahan.
Link / Document Optional Referensi eksternal atau dokumen.
Rating / Mood Optional Data refleksi pribadi.
Rule: user tidak boleh dipaksa mengisi seluruh metadata. Prinsip input HoL adalah "catat cepat dulu, perkaya kemudian".

13

Technical Architecture

Frontend

Responsive web application optimized for desktop and mobile, with no horizontal overflow.

AI Layer

Gemini API digunakan untuk natural-language activity parsing dan tahap berikutnya untuk life insights.

Persistence

Activity data harus tersimpan secara persistent agar history dan report dapat dibangun dari waktu ke waktu.

Reporting Layer

Data activity menjadi sumber grafik, aggregation, trend analysis, dan AI insights.

Security requirement: Gemini API key tidak boleh diekspos di client-side production jika arsitektur production menggunakan backend. Request AI sebaiknya melewati secure server-side layer.
14

Privacy & Security

Personal Data

HoL dapat menyimpan data kehidupan pribadi seperti aktivitas, lokasi, biaya, foto, catatan, dan mood. Data harus diperlakukan sebagai data pribadi.

AI Data Handling

Input yang dikirim ke Gemini harus dikendalikan dengan jelas, dan arsitektur production tidak boleh menaruh secret API key secara terbuka di browser.

Authentication

Jika HoL menjadi produk multi-user, authentication dan user-level data isolation menjadi requirement production.

Database Security

Jika menggunakan Supabase atau database exposed API, access policy/RLS harus diterapkan sesuai model data.
