💡 Soal Sonnet 4.6 / Versi Legacy
Sonnet 4.6 itu versi lama (Legacy) dari Sonnet 5 — bukan pilihan "lebih hemat". Keduanya ada di menu model yang sama, sama-sama bagian dari kuota Pro standar, tidak ada bedanya di sisi kuota. Bedanya: Sonnet 5 sudah menggantikan 4.6 sebagai versi current, kemampuannya kemungkinan setara atau lebih baik. Tidak ada untung pakai versi legacy kecuali kamu punya alasan konsistensi khusus dengan project lama. Detail siklusnya lihat section Model Lifecycle di bawah.
Model Lifecycle

Kenapa Versi Lama Sebaiknya Di-skip

Setiap model punya siklus hidup. Memahami ini menjawab kenapa Sonnet 4.6 di-drop dari rotasi, kenapa Opus 4.8, 4.7, 4.6, dan Opus 3 semuanya legacy sekaligus — bukan cuma yang paling lama — dan kapan model yang biasa kamu pakai perlu di-cek ulang.

Effort Level

Bukan Cuma Model — Effort Juga Ngefek

Effort (Low/Medium/High) mengatur seberapa dalam Claude "mikir" sebelum jawab. Model + effort itu dua tombol berbeda yang sama-sama pengaruhi kuota.

🟢 Low
Jawaban cepat, minim "mikir". Pas untuk kerjaan receh: rename, format, fix typo, pertanyaan simpel yang jawabannya sudah jelas.
🔵 Medium
Paling seimbang untuk kerja harian yang campuran. Default yang aman untuk hampir semua task coding & brainstorm ringan.
🟡 High
Mikir paling dalam, paling boros. Simpan untuk masalah yang jawabannya belum jelas bentuknya — bukan task rutin.
💡 Key Insight
Toggle Thinking manual sebaiknya dimatikan di effort Medium ke atas — model sudah otomatis mikir kalau perlu (adaptive). Toggle manual bisa bikin dia mikir lebih dari yang dibutuhkan untuk task simpel, buang-buang kuota tanpa hasil lebih baik.
Praktik

Dipetakan ke Kerjaan Kamu Sehari-hari

Task yang sering muncul di workflow kamu, dipetakan ke model yang paling pas — bukan yang paling canggih.

TaskModelAlasan
Summary chat yang sudah panjang ⚡ Haiku 4.5 Cuma perlu compile & ringkas apa yang sudah dibahas — bukan reasoning baru. Sonnet di sini overkill.
Cari-cari info / cross-check dari chat lama ⚡ Haiku 4.5 Sama seperti summary — mencari & menyusun ulang info yang sudah ada, bukan menciptakan hal baru.
Report text-only (tanpa HTML) ⚡ Haiku 4.5 Kalau strukturnya simpel (poin-poin, ringkasan naratif) tanpa perlu presisi layout, Haiku cukup.
HTML dari template/standar yang sudah ada 📝 Sonnet 5 Butuh presisi struktur HTML/CSS, konsistensi class & style dengan file existing — ini kekuatan Sonnet.
HTML simple / report dengan sedikit styling ⚡ Haiku 4.5 Kalau HTML-nya cuma layout dasar tanpa mengikuti design system spesifik, Haiku biasanya sudah cukup rapi.
Coding fitur/modul baru dari spec jelas 📝 Sonnet 5 Eksekusi kode yang butuh logika benar dan konsisten dengan codebase — wilayah utama Sonnet.
Brainstorm struktur data / arsitektur awal 🎼 Opus 5 Keputusan besar yang menentukan arah project — worth investasi kuota lebih di awal, biar tidak salah fondasi.
Patokan kasar: kalau task-nya "susun ulang yang sudah ada" → Haiku. Kalau "buat yang baru dengan presisi" → Sonnet. Kalau "putuskan arahnya" → Opus.
Escalation

Kapan Naik Balik ke Opus

Sonnet cukup untuk mayoritas kerjaan. Tapi ada sinyal jelas kapan waktunya naik tier lagi.

🔺 Sinyal Naik ke Opus
🔁Sonnet stuck 2-3× di masalah yang sama — biasanya tanda masalahnya di desain/struktur, bukan di penulisan kode.
🐛Bug yang lintas beberapa file dan sumbernya belum ketahuan sama sekali.
🧩Butuh keputusan trade-off baru yang tidak terduga di tengah coding — misal ternyata struktur data awal tidak cukup untuk fitur baru.
✅ Bukan Sinyal Naik ke Opus
📄Typo, error syntax kecil, atau bug yang penyebabnya sudah jelas — itu tetap wilayah Sonnet (atau Haiku).
📏Project-nya "besar" secara volume (banyak modul) — kalau tiap modul digarap bertahap, tiap potongannya tetap sedang-sedang saja untuk Sonnet.
Quick Decision

Bingung Pilih? Ikuti Ini

Tiga pertanyaan cepat untuk memutuskan model tanpa harus baca ulang semua tabel di atas.

1
Apakah kamu sedang memutuskan arah, atau menjalankan yang sudah jelas?
→Belum jelas arahnya, masih banyak opsi 🎼 Opus 5
→Sudah jelas, tinggal eksekusi Lanjut ke Q2 ↓
2
Apakah hasilnya perlu presisi struktur (kode, HTML mengikuti template, logika)?
→Ya, perlu presisi & konsistensi 📝 Sonnet 5
→Tidak, cuma susun ulang info Lanjut ke Q3 ↓
3
Apakah ini rangkuman, pencarian info, atau kerjaan kecil (rename/format)?
→Ya ⚡ Haiku 4.5
→Tidak yakin 📝 Sonnet 5 (aman default)
🎯 Aturan Simpel Kalau Masih Ragu
Kalau ragu antara dua tier — pilih yang lebih rendah dulu. Kalau hasilnya kurang, naik satu tingkat. Ini lebih hemat daripada default ke tier tinggi "biar aman", karena kebanyakan task kamu (compro, shop sederhana, web app kantor) memang tidak butuh tier atas.
