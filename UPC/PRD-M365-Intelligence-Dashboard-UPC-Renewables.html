Microsoft 365 Intelligence Dashboard

A unified operations command center for IT management at UPC Renewables Indonesia — surfacing what needs attention today across email, calendar, tasks, files, and infrastructure health.

01

Executive Summary

UPC Renewables Indonesia operates critical energy infrastructure across three sites — Bali, Jakarta, and Sidrap — with a single IT Manager responsible for systems, security, and operations across all of them. Today, that visibility is scattered across Outlook, Teams, a task list, and manual server checks. Nothing is missed because of a lack of tools; things are missed because no single screen tells the IT Manager what actually needs attention right now.

This document proposes a browser-based, mobile-friendly command center that connects directly to Microsoft 365 (via Microsoft Graph) and to the three production servers, and distills all of it into one prioritized view: what's urgent, what needs follow-up, and what's just for awareness — refreshed automatically throughout the day.

One login, one screen

Sign in once with a Microsoft work account. No separate password to manage, no second system to check.

Built for how you already work

Reads directly from Outlook, Calendar, Tasks, and OneDrive — no new place to enter data.

Infrastructure included

The three Jakarta servers are monitored on the same screen, without ever exposing their IP addresses in the app itself.

02

Problem Statement

A one-person IT function covering three sites has no room for information that hides in the wrong app. The core problem is not a missing tool — it's fragmentation and lack of prioritization.

Fragmented visibility

Email, calendar, tasks, files, and server status each live in a different place, checked separately and manually.

No prioritization signal

A full inbox and a full calendar don't say what's actually urgent — everything looks equally important until it's read.

Manual infrastructure checks

Server health across three sites is checked reactively, not surfaced proactively in one place.

Single point of coverage

One person, three locations. Time spent switching between systems is time not spent resolving issues.

Users & Personas

Version 1 is scoped for a single user. The architecture is designed so additional users can be added later without a redesign.

Primary — IT Manager V1

Sole user in V1. Holds Microsoft 365 admin rights on the UPC Renewables Indonesia tenant, giving direct access to configure the required app registration and permissions.

Future — Additional staff V2+

Potential expansion to other IT or management staff once V1 is validated. Would introduce role-based views (e.g. a management-facing summary vs. an IT-facing technical view).

Scope & Roadmap

Features are grouped into three tiers, ordered by how much value they deliver relative to their implementation effort and permission requirements. Filter the list below to focus on one tier at a time.

V1 Sign-in & Identity

Single sign-on with Microsoft work account (MSAL). Replaces the current dual login with one secure flow.

V1 Inbox Highlights

Unread count, sender, subject, internal vs. external flag.

V1 Calendar

7-day schedule view, today's meetings, tentative event flagging.

V1 Microsoft To Do / Tasks

Task list with overdue and due-today grouping — replaces the current unconnected task placeholder.

V1 OneDrive Recent Files

Recent and shared files, storage quota. Metadata only — files open in Microsoft 365, never stored in the dashboard.

V1 User Profile & Presence

Real name, photo, job title, and the signed-in user's own availability status.

V1 Server Monitoring

Up/down status for the three Jakarta servers, checked on a timer via a secure intermediary — see Section 08.

V1 AI Daily Briefing

Automated narrative summary of the day's priorities, generated from the Attention Center's rule engine. Data flow disclosed in Section 11.

V1 Attention Center

The prioritization engine that turns raw data into a High / Follow-up / FYI list. See Section 07.

V2 Teams Chat flagged

Recent chats and unread count. Requires verification against Microsoft's current Graph API access terms for message content before commitment — see Section 13.

V2 Planner

Task boards, assigned tasks, overdue tracking — conditional on confirming UPC Renewables actively uses Planner.

V2 SharePoint Documents

Recent activity across SharePoint sites. Broader scope than OneDrive; higher implementation effort.

V2 Multi-user Access

Role-based views for additional staff beyond the initial IT Manager user.

V3 Historical Uptime Log

Trend view of server availability over time, built from the same monitoring data collected in V1.

V3 Teams Channel Activity Feed

Office-wide activity feed from Teams channels. Same access-policy caveat as V2 Teams Chat.

V3 Employee Directory

Static organizational reference — low priority for a "realtime" dashboard, suited to a separate page.

07

Attention Center Logic

The dashboard's core differentiator is not displaying more data — it's turning email, calendar, tasks, and files into one prioritized list. This engine is rule-based, not AI-based: deterministic, free to run, and never subject to hallucination. AI (Section 06) is used only to narrate the output of these rules, never to decide priority.

TierTrigger conditions
HighMeeting starting within 30 minutes · Task overdue · Unread email flagged High Importance
Follow-upEmail unread for more than 24 hours · Task due today · Meeting marked Tentative
FYINew file added in the last 24 hours · Meeting scheduled for tomorrow
Design principle

Thresholds above are a starting proposal, not a fixed spec — they should be reviewed and tuned with the IT Manager once real inbox/calendar volume is observed during pilot use.

08

Server Monitoring

Three production servers in Jakarta, monitored via public IP. Browsers cannot perform ICMP ping, and a direct fetch() from the dashboard to a public IP will typically fail due to CORS. Monitoring is therefore handled by an intermediary — see the data flow in Section 09.

  1. Scheduled checkA server-side script polls each of the three servers on a timer (e.g. every 5 minutes) — not the browser.
  2. Status written to a private storeEach check's result (up / down / response time) is written to a datastore the dashboard does not expose publicly.
  3. Dashboard reads status onlyThe dashboard fetches a simple status JSON — never the server IPs themselves, which stay out of client-side source code entirely.
Non-negotiable constraint

Because UPC Renewables operates energy infrastructure, the three server IP addresses must never appear in the dashboard's HTML/JS source — anyone using "View Source" on the public file would otherwise see them. This is treated as a hard requirement, not a preference.

09

Architecture & Data Flow

The dashboard is a single-file, standalone web app — no backend server of its own. Two distinct authentication paths handle two different needs: the browser talks to Microsoft Graph directly with the signed-in user's own permissions, while a separate proxy handles anything that needs a secret (AI summarization, server status).

Hosting

Static hosting on Anabhidev's domain for trial. A migration path to a UPC Renewables–controlled domain can be scoped separately if the pilot proceeds.

Token storage

sessionStorage only — cleared when the browser tab closes. Nothing persisted to disk or a database.

Security & Data Privacy

Data sent to a third party — disclosed explicitly

The AI Daily Briefing feature sends email subject lines, sender names, and calendar event titles to Google's Gemini API for summarization, via the Anabhidev-controlled Google Apps Script proxy. No message bodies or attachments are sent. This is disclosed here so it can be reviewed against UPC Renewables' data handling policy before the feature is enabled in production. It should ship as a feature that can be switched off.

ControlApproach
AuthenticationMicrosoft sign-in (MSAL) only — no client-side password comparison
Token storagesessionStorage, cleared on tab close, never written to disk
Server IP addressesNever present in client-side source — held only in the proxy layer's private configuration
Tenant & app identifiersClient ID and tenant ID are visible in the client (standard for public client apps) — client secret is never present in the browser
Data persistenceNone. The dashboard reads live from Microsoft Graph on each load; nothing is stored in a database
TransportHTTPS enforced for all connections, including the proxy endpoint
12

Non-Functional Requirements

Mobile-first

Full functionality on a phone browser; layout locked to viewport width with no horizontal scroll.

Responsive desktop

Content uses full available browser width rather than a fixed centered column.

Refresh behavior

Auto-refresh on a configurable interval, with Graph API rate-limit retry handling.

Browser support

Current versions of Chrome, Edge, Safari, and Firefox on desktop and mobile.

Accessibility

Keyboard navigable, visible focus states, WCAG-checked color contrast throughout.

Performance

No unnecessary polling; requests batched and cached within the session where possible.

13

Assumptions, Dependencies & Risks

Assumption — tenant access

The primary user holds administrator rights on the UPC Renewables Indonesia Microsoft 365 tenant, which is expected to make the required App Registration and permission approvals straightforward compared to a typical external-vendor engagement.

Risk — Teams message access policy

Microsoft periodically adjusts access terms for programmatic access to Teams chat and channel content, particularly around metered or protected API scenarios. The specific terms applicable to this deployment must be re-verified against current Microsoft Learn documentation at build time, before Teams Chat (Section 05, V2) is committed to a client-facing timeline.

Dependency — feature usage confirmation

Planner and SharePoint modules (Section 05, V2) depend on confirming that UPC Renewables actively uses those tools day-to-day. Building against an unused tool produces a feature with no ongoing value.

Assumption — hosting

The trial/pilot phase is hosted on Anabhidev's own domain. A production deployment on UPC Renewables-controlled infrastructure or domain is treated as a separate follow-on scope item.
